# ML → Backend Integration Contract

## Railway Predictive Maintenance System

This document defines the contract between the Machine Learning layer and the Node.js backend.

---

# 1. ML Output Files

The ML pipeline currently produces these backend-consumable artifacts.

### Primary prediction files

- `outputs/asset_risk_scores.csv`
- `outputs/ensemble_predictions.csv`
- `outputs/asset_explanations.csv`

### Configuration / metrics

- `outputs/ensemble_metrics.json`
- `outputs/risk_scoring_config.json`
- `outputs/explainability_summary.json`

---

# 2. Asset Risk Data

## Source

`outputs/asset_risk_scores.csv`

## Schema

| Field | Type | Description |
|---|---|---|
| asset_id | string | Unique railway asset identifier |
| snapshot_date | date | Prediction snapshot date |
| actual | integer | Historical ground-truth target |
| predicted_probability | float | Predicted maintenance probability |
| predicted_class | integer | Binary prediction |
| risk_probability | float | Probability used for risk scoring |
| risk_level | string | LOW / MEDIUM / HIGH / CRITICAL |
| risk_score | float | Probability expressed as percentage |
| recommended_action | string | Recommended maintenance action |

### Example

```json
{
  "asset_id": "AST027697",
  "snapshot_date": "2026-05-25",
  "predicted_probability": 0.557230,
  "risk_probability": 0.557230,
  "risk_level": "HIGH",
  "risk_score": 55.72,
  "recommended_action": "Schedule inspection within 7 days"
}
```

# 3. Ensemble Prediction Data

## Source

`outputs/ensemble_predictions.csv`

The weighted ensemble combines three models:

```

```
LightGBM       50%
Temporal CNN   30%
Random Forest  20%
```

## Schema

| Field | Type | Description |
|---|---|---|
| asset\_id              | string  | Unique asset identifier    |
| snapshot\_date         | date    | Prediction snapshot date   |
| actual\_maintenance    | integer | Historical target          |
| lgb\_probability       | float   | LightGBM probability       |
| cnn\_probability       | float   | Temporal CNN probability   |
| rf\_probability        | float   | Random Forest probability  |
| ensemble\_probability  | float   | Final weighted probability |
| predicted\_maintenance | integer | Final binary prediction    |
| threshold              | float   | Classification threshold   |
| risk\_level            | string  | Final risk category        |

## Ensemble Formula

```

```
ensemble_probability =
    0.50 × LightGBM probability
  + 0.30 × Temporal CNN probability
  + 0.20 × Random Forest probability
```

# 6. Recommended Maintenance Actions

Risk levels are mapped to operational recommendations.

```

```
LOW
→ Continue routine monitoring

MEDIUM
→ Monitor asset condition and plan inspection

HIGH
→ Schedule inspection within 7 days

CRITICAL
→ Prioritize immediate inspection / maintenance
```

These recommendations are generated by the ML risk-scoring layer and should be displayed by the backend without changing the underlying prediction.
```

```
# 16. Final ML → Backend Contract

The ML layer generates the prediction artifacts.

The Node.js backend consumes these artifacts and exposes them through REST APIs.

The frontend consumes the backend APIs and displays the results to users.

## The backend should NOT:

```

```
Retrain ML models
Modify ML probabilities
Change risk categories
Change prediction thresholds
Generate alternative predictions
```

## The backend SHOULD:

```

```
Read ML prediction artifacts
Expose prediction data through APIs
Provide asset-level filtering
Provide risk-level filtering
Provide prediction details
Provide explanation details
Return ML metrics when required
